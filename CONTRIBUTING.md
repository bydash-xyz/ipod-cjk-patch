# Contributing to iPod CJK Patch

Thanks for helping! Bug reports, missing characters, translations, and especially **tests and
ports for other iPods and firmware versions** are all welcome (see
[Porting](#porting-to-another-ipod-or-firmware)).

## A human summary is required

**Every issue and pull request must start with at least one sentence written by a person** (not
generated by an AI tool), in your own words. Say what you saw or what you changed, and why.
Any language is fine, and so is imperfect English. AI tools may help with the rest of the
description, the code or the investigation. But the maintainers need to know that a person
looked at the problem and stands behind the report. Issues and PRs without a human summary will
be closed. You can reopen once you add one.

The issue and PR templates have a **Summary (written by you)** field for this.

## Reporting a problem

Open an issue with:

- your human summary (see above)
- your iPod model and capacity (5G or 5.5G), and how it's formatted (Mac or Windows)
- whether you flashed the released build (`tools/build.py` says "matches the released build") or
  a modified one
- **a photo of the screen**. Rendering bugs are often 1px, so a sharp close-up helps most.
- the exact text (title/artist/album or lyric line) that looks wrong

Please don't attach firmware images or partition backups. They contain Apple's copyrighted
firmware.

## Missing characters

If a character doesn't show up, or shows up small in menus:

1. Run `tools/scan_library.py` on your music (see the README) to list what your firmware can't
   draw.
2. Add the characters to `charsets/lyrics_extra.txt` (lyrics) or `charsets/menu.txt` (menus).
3. Rebuild, check `build/before-after.png` or test on your iPod, and open a pull request.

The lyric fonts have a fixed size budget (see "Firmware notes" in the README). The build will
fail with a clear error if a change doesn't fit.

## Porting to another iPod or firmware

This is the most valuable kind of help. Only one iPod has been tested so far: an iPod Video
5.5G with firmware 1.3 (`iPod_25.1.3.ipsw`), Mac-formatted. These are the parts tied to that
setup:

| What | Where | Notes |
|---|---|---|
| Stock IPSW URL and hashes | `IPSW_*` in `tools/build.py` | One pinned firmware; a port adds another |
| Firmware directory at `0x4200`, osos data at `0x5000` | `tools/ipodfw.py`, `tools/build_unified.py` | `build_unified.py` asserts the osos layout |
| Font registry address `0x6a6480–0x6a6660` | `REGISTRY` in `tools/build_unified.py`, `tools/render_preview.py` | Version-specific; ideally found by searching instead of hardcoded |
| 12px CJK font families (AppleGothic, AppleLiGothicMedium, Hei, Osaka) | `FAMILIES` in `tools/build_unified.py` | List them on your firmware with `tools/pixofont.py <firmware>` |
| Lyrics' Latin/symbol font Podium Sans 16, bottom-aligned with the 12px fonts | `TARGET` in `tools/build_latin.py`, `tools/render_preview.py` | Found from an on-device photo; check yours the same way |
| Glyph strip limit 31836px | `STRIP_LIMIT` in `tools/build_unified.py` | Measured on 1.3; likely the same on other 5G firmware |
| Menu font `/Resources/Fonts/CJK.ttf` (18px EBDT) | `tools/build.py`, `tools/extend_cjk_ttf.py` | |
| Partition layout: firmware on `s2`, music on `s3` (Mac-formatted) | `tools/backup_and_flash.sh` | Windows-formatted iPods use an MBR layout |
| On-device image offset `devOffset + 0x200` | `tools/install_firmware.py` | Read from the device's own directory, so it may already work |

A good way to start:

1. Open a **Support another iPod / firmware** issue with your model, capacity, formatting and
   firmware version.
2. Run `uv run python -I tools/pixofont.py <your Firmware file>` and attach the output. It shows
   whether the font format and families match.
3. For the flash path, attach `diskutil list` output for the iPod. **Don't flash** a build for
   your model until the port has been reviewed, and keep a partition backup.

Ports should keep the existing safety checks: verify the stock image byte for byte before
writing, write only changed sectors, and read back to verify. Add the new firmware as an extra
pinned target rather than replacing 1.3.

## Development setup

You need macOS (the menu font is rasterized from the system's Hiragino Sans GB) and
[uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/bydash-xyz/ipod-cjk-patch.git
cd ipod-cjk-patch
uv sync
uv run python -I tools/build.py
```

## Pull requests

Before opening a PR:

- [ ] the description starts with your own human-written summary (see above)
- [ ] `uv run python -I tools/build.py` succeeds
- [ ] `uvx ruff check --select E,F,W --line-length 120 tools/` passes
- [ ] if the firmware output changed **on purpose**: `EXPECTED_SHA256` in `tools/build.py`, the
      SHA256 in all four READMEs and `docs/before-after.png` are updated (copy
      `build/before-after.png`)
- [ ] if the output **shouldn't** have changed: the build still reports "matches the released build"
- [ ] user-facing changes are reflected in all READMEs. If you can't translate, update
      `README.md` and say so in the PR, and someone else will update the translations.
- [ ] say how you tested: build only, or flashed to a real iPod (which model)

Keep PRs focused. One fix or feature per PR is easier to review and to test on hardware.

Code style: follow the existing scripts. That means small single-purpose tools, a docstring with
usage at the top, and comments that explain firmware quirks. [AGENTS.md](AGENTS.md) lists the
invariants the firmware enforces; please read it before changing `build_unified.py`,
`pixofont.py` or `install_firmware.py`.

## What can't be accepted

- Apple firmware, partition dumps, or files extracted or derived from them (including fonts made
  from Apple fonts)
- Font files committed to the repository, or fonts whose license doesn't allow redistribution.
  New glyph sources should be OFL or similar. Download them in `tools/build.py` from a pinned
  release with a SHA256, and add their license under `third_party/`.

## Translations

READMEs exist in English, Simplified Chinese, Japanese and Korean. New languages are welcome:
copy `README.md` to `README.<lang>.md`, translate the prose but keep commands, paths and hashes
unchanged, and add the language to the switcher line in every README.
